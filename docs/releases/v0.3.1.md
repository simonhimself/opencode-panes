# OpenCode Panes v0.3.1

Fixes client-side form handling in browser artifact previews. The published v0.3
tag remains unchanged.

## Fix

Standard forms now support required-field validation, submit-button clicks,
Enter-key submission, and `requestSubmit()` with JavaScript submit handlers.
Both the preview iframe and the served document's sandbox permit `allow-forms`.

Panes-served documents retain CSP `form-action 'none'`, so actual native GET/POST
form submissions remain blocked, including `HTMLFormElement.prototype.submit()`.
Same-origin privileges, popups, and top navigation remain ungranted. Third-party
documents use their own CSP; existing HTTPS access and embedding are unchanged.

## Updating

Deploy the new web viewer and Worker together, then reload the dashboard or share
page. Existing artifact content does not need to be changed or reuploaded.
This patch does not change plugin behavior, database schema, credentials, or
Access configuration. No migration or plugin reinstall is required for the fix.

## Verification

- 174 automated tests cover the Worker, client, contracts, and plugin.
- Five Chromium scenarios cover embedded/direct previews, both old-policy
  negative controls, and the documented third-party CSP distinction.
- Sixteen native GET/POST attempts from Panes-served fixtures were blocked with
  zero requests reaching the controlled owner-route or cross-origin receivers.
- Parent-DOM access remains blocked. The controlled third-party test intercepts
  its HTTPS traffic locally instead of sending it to an external service.

The browser regression script imports production headers; the normal Worker and
UI tests separately verify their actual serving and embedding paths. Firefox and
WebKit were not covered by this focused regression.
